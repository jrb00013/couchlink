# Session log 2026-10-26: RPCS3 5080 driver, BO2 play25, capture hang, MK

## 1. RTX 5080 not visible (WSL and Windows)
- Symptom: `nvidia-smi` -> "Failed to initialize NVML" in WSL and Windows. The 5080 showed `Status=Error`,
  Code 31 (`CM_PROB_FAILED_ADD`), problem status `0xC0000182`.
- Evidence (`C:\Windows\INF\setupapi.dev.log`): failing since 2026-10-17 ~23:27, right after Windows bound the card to
  `nvam.inf` 32.0.15.9191 (oem174) while the display component installed from `Downloads\nvidia-591.86` is 9186
  (`nv_dispi.inf` oem104, `nvami.inf` oem181). Mixed declarative DCH packages -> config error.
- A plain `pnputil /restart-device` did not help. Fix: `pnputil /delete-driver oem174.inf /uninstall`, then `/scan-devices`.
  The card bound to oem181 (9186). `nvidia-smi` then reports RTX 5080 Laptop GPU, driver 591.86, in WSL and Windows.
- Follow-up: Windows says a reboot completes the uninstall. Windows Update may re-offer 9191; repeat the removal if
  the card goes back to Code 31.
- Verified afterwards: RPCS3 log `Adapter: NVIDIA GeForce RTX 5080 Laptop GPU`; capture uses the same adapter's NVENC engines.

## 2. BO2 on RPCS3 `19984-play25` (fork branch `play25-streak-across-sleep`, CI run 39365096991)
- Staged with `tools/rpcs3-debug/stage-build.sh`, switched with `switch-rpcs3.cmd 19984-play25`, BO2 launched, stack started

- The reported "freeze" was NOT an emulator freeze: RPCS3 was 55 FPS and responding, stwcx failures ~50k/s (the real

- play25 is still unproven on a full BO2 session.

## 3. Capture hang: keep_rendering ping-pong (PR #107, commit 84feb1d)
- The win-capture log showed `restored the captured window` / `window minimized - parked off-screen` alternating every
  ~200 ms, with the crop flipping between 2011x1235 and 173x32.
- Cause in code: `park()` stored the window placement while minimized (`showCmd = SW_SHOWMINIMIZED`), so `restore_now()`
  re-minimized the window, the watcher re-parked it, and so on.
- Fix: store `SW_SHOWNORMAL` / `SW_SHOWMAXIMIZED` instead, and `SW_RESTORE` if the window is still iconic after restore.
- Caveat: the trigger that first minimized the window was not identified (the user did not minimize it). The fix removes the
  self-sustaining loop; it is unproven that it was the only cause of the hang.
